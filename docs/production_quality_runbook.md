# DAR.EST — دليل الجودة والاسترداد التشغيلي

## الغرض والنطاق

يوضح هذا الدليل الإجراء التشغيلي عند ظهور خلل في منصة DAR.EST، وكيفية التحقق من الإصدار قبل النشر أو الرجوع إلى نقطة مستقرة. يقتصر على تطبيق الويب متعدد الشركات، ولا يستبدل ضوابط قاعدة البيانات أو المراجعة البشرية للعمليات المالية.

> **قاعدة الاسترداد:** يجب حفظ نقطة استرجاع مستقرة بعد اكتمال الاختبارات والبناء والمعاينة. يعيد الرجوع ملفات التطبيق وإعداداته فقط؛ لا يعيد مخطط قاعدة البيانات أو البيانات التشغيلية إلى الوراء تلقائياً.

| المرحلة | الإجراء | معيار الإكمال |
|---|---|---|
| التحقق قبل النشر | تشغيل `pnpm test -- --run` ثم `pnpm build`، ومراجعة المسارات العامة ومساحة العمل ذات الصلة على سطح المكتب والهاتف. | نجاح الاختبارات والبناء، وعدم وجود خطأ واجهة متكرر في المسار الذي تغيّر. |
| التحقق من العزل | مراجعة الإجراء الخادمي وصلاحية الشركة المطلوبة، وتشغيل اختبارات الصلاحيات وعقود المورد ذي الصلة. | لا تُعرض بيانات شركة أو سجل تدقيق لمستخدم لا يملك الصلاحية. |
| تشخيص العطل | توثيق الوقت والمسار وهوية الشركة المتأثرة، ثم البحث في سجلات الخادم وواجهة المتصفح باستخدام `X-Request-ID` إن وُجد. | تحديد ما إذا كان العطل في الواجهة أو عقد tRPC أو قاعدة البيانات أو مزود خارجي. |
| تخفيف الأثر | إيقاف الإجراء الخطر مؤقتاً عبر الواجهة أو حارس الصلاحية إن أمكن، من دون حذف سجلات أو تنفيذ ترحيل عكسي غير مراجع. | لا تستمر عملية خاطئة أو كشف محتمل للبيانات. |
| الاسترداد | الرجوع إلى آخر نقطة استرجاع مستقرة من إدارة المشروع، ثم إعادة تشغيل المعاينة والتحقق من المسار المتأثر. | يعمل التطبيق المستعاد، وتبقى بيانات قاعدة البيانات كما هي قبل خطوة الاسترداد. |
| المعالجة اللاحقة | إضافة اختبار يعيد إنتاج العطل، ثم تنفيذ الإصلاح وبناء الإصدار وحفظ نقطة استرجاع جديدة. | يوجد اختبار يمنع عودة العطل وتوثيق موجز للسبب والحل. |

## حدود السلامة للترحيلات والبيانات

تُنفذ الترحيلات الإضافية بعد قراءة SQL المتولد ومراجعته. عند فشل ترحيل أو ظهور خطأ تشغيلي بعده، لا تستخدم الرجوع إلى إصدار التطبيق لمحاولة حذف الجدول أو العمود الجديد. بدلاً من ذلك، يحلل فريق التشغيل التبعيات، ويُنشئ ترحيلاً أمامياً مصححاً بعد نسخة احتياطية مناسبة للبيئة المستهدفة.

تُعامل أحداث التحصيل وعكس الدفعات وسجل إصدارات الموارد كسجلات عمل لا تُحذف لاسترجاع حالة سابقة. يجب أن يمر التصحيح بإجراء تعويضي أو مراجعة جديدة حتى يبقى أثر التدقيق متسقاً.

## قائمة المسارات الحرجة

| المسار | ما يجب التحقق منه | الحارس الأساسي |
|---|---|---|
| `/checkout` و`/account` | حالة المفتاح والاشتراك، ورسائل التحميل أو الفشل. | التحقق الخادمي من المفتاح والاشتراك. |
| `/workspace` | بوابة الشركة النشطة، القائمة الجانبية، والإشعارات دون كشف بيانات خارج الشركة. | عضوية الشركة والصلاحيات الدقيقة. |
| `/workspace/reports` | مؤشرات من استعلامات نطاق الشركة فقط، وتصدير CSV مجمع بلا بيانات أفراد. | بوابة الشركة النشطة والاستعلامات المقيدة بالشركة. |
| `/workspace/documents` | صلاحية المستند وروابط الوصول الموقعة والإصدارات. | `documents.read` و`documents.write`. |
| `/owner` | إدارة المفاتيح والاشتراكات والسجل ضمن دور المالك. | إجراء الإدارة المحمي. |

## حدود التحقق المعروفة

تبقى ثلاثة اختبارات تكامل اختيارية متخطاة عمداً في بيئات لا تهيئ قاعدة بيانات اختبار منفصلة أو مزود Ollama خارجي. لا تستخدم قاعدة الإنتاج لتشغيلها. كما أن الشراء في المنتج يعتمد مسار التفعيل اليدوي ومراجعة المالك؛ لا ينبغي تفسير فتح رابط أو إدخال طلب على أنه تأكيد مالي تلقائي.

## سجل المسؤولية

عند إغلاق حادث أو نشر إصلاح، يسجل المنفذ رقم نقطة الاسترجاع، أثر المستخدم أو الشركة، الاختبارات المنفذة، وأي ترحيل طبق. يساعد ذلك على ربط القرار التشغيلي بسجل التدقيق وسجل إصدارات الموارد بدلاً من الاعتماد على الذاكرة أو المحادثات.

## تحقق الجودة المنفذ في الإصدار الحالي

| التحقق | الحالة | الدليل |
|---|---|---|
| ترحيل سجل إصدارات الموارد | مكتمل | فحص قاعدة البيانات أكد جدول `company_resource_revisions` وقيد التفرد وفهرسي المورد والمنفذ؛ ويحميه `server/companyResourceRevisions.migration.contract.test.ts` من SQL الهدمي. |
| عزل نقاط الدخول الحديثة | مكتمل | `server/tenantIsolation.test.ts` يثبت بوابات الشركة والصلاحيات للتقارير والإشعارات وسجل الإصدارات. |
| مراقبة مسار التقارير | مكتمل | `server/observabilityContracts.test.ts` يثبت حالة التمكين والتحميل والفشل وإعادة المحاولة، إضافة إلى عقود الصحة وسياق الطلب. |
| دورة التحقق | مكتمل | نجحت 144 حالة اختبار، مع 3 اختبارات تكامل اختيارية متخطاة عمداً، ونجح بناء الإنتاج. |
